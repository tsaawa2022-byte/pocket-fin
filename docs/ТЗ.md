# Техническое задание
## Карманный финансовый помощник (PocketFin)

**Версия:** 1.0 · **Дата:** 23.11.2026
**Платформа:** веб-приложение (Spring Boot + Angular), мультпользовательское

---

## 1. Общие сведения

### 1.1. Назначение
Веб-приложение для персонального учёта финансов, которое получает данные о банковских операциях через пересланные пользователем SMS в Telegram-бота, структурирует их и выдаёт персональные рекомендации по финансовой грамотности для накоплений и сокращения неосознанных трат.

### 1.2. Проблема
Пользователь не отслеживает мелкие и регулярные траты, из-за чего не копит деньги. Ручной учёт утомителен и быстро бросается.

### 1.3. Решение
- Минимальное усилие на ввод: переслал SMS боту — операция учтена.
- Автоматическая категоризация и статистика.
- Персональные рекомендации в моменте и в виде еженедельного дайджеста.

### 1.4. Целевая аудитория
Физические лица 18–45 лет, несколько пользователей (не пет-проект), регистрация обязательна.

---

## 2. Канал ввода транзакций

Веб-приложение не имеет доступа к SMS. Канал ввода MVP — **Telegram-бот**:

1. Пользователь регистрируется в веб-приложении и получает личный код привязки.
2. Пользователь пишет боту `/start <код>` — Telegram-аккаунт привязывается к учётной записи.
3. Пользователь пересылает банковские SMS боту.
4. Бот сохраняет сырое сообщение, парсер извлекает: тип операции (списание/зачисление), сумму, валюту, карту/счёт (маскированный), остаток, банк, дату.
5. Нераспознанные сообщения помечаются и предлагаются к ручному разбору в веб-интерфейсе.

> Архитектура парсера и API канал-независимы: позже добавляются Android-компаньон (чтение SMS напрямую) и/или импорт CSV без переработки ядра.

### 2.1. Поддерживаемые банки (MVP)
Сбербанк, Тинькофф, Альфа-Банк. Шаблоны — конфигурация (regex + извлечение полей), добавление банка = добавление конфига.

### 2.2. Пример распознаваемого SMS
`Покупка на сумму 1 250,50 RUR. Карта *4521. Баланс: 23 400,00 RUR. T-Bank`

## 3. Функциональные требования

**FR-1. Регистрация и аутентификация**
- Регистрация по email + пароль.
- JWT: access 15 мин + refresh 30 дней.
- Профиль: имя, основная валюта, часовой пояс.
- Роли: `USER`, `ADMIN` (пользователи, метрики, логи парсера).
- Код привязки Telegram (одноразовый, TTL 24 ч).

**FR-2. Учёт доходов и расходов**
- Список операций: фильтры (период, тип, категория, банк, диапазон суммы), поиск по тексту.
- Ручное добавление/редактирование/удаление.
- Автокатегоризация по пользовательским правилам (маппинг «merchant → категория»).
- Баланс по счетам из поля «Баланс» SMS.
- Категории: системный набор (Еда, Транспорт, Жильё, Подписки, Развлечения, Одежда, Здоровье, Прочее) + пользовательские.

**FR-3. Telegram-бот**
- Команды: `/start`, `/link <код>`, `/unlink`, `/help`, `/stats`.
- Фото/скриншоты — пост-MVP.
- Подтверждение парсинга ответом: «✅ −1 250 ₽ · Еда · остаток 23 400 ₽».
- Антифлуд: ≤ 100 сообщений/мин на аккаунт.

**FR-4. Статистика и графики**
- Дашборд: баланс, расходы/доходы месяца, динамика по дням.
- Круговая диаграмма расходов по категориям.
- Столбчатая диаграмма доходы/расходы по месяцам.
- Топ-5 категорий с % от расходов, сравнение с прошлым месяцем.

**FR-5. Движок рекомендаций (правила)**
- R1. Правило 50/30/20 — доли обязательных/желаний/накоплений вне нормы.
- R2. Мелкие траты — операции < 500 ₽ превышают X% бюджета.
- R3. Подписки — забытые регулярные списания.
- R4. Рост категории > 30% к прошлому месяцу.
- R5. Нет накоплений N месяцев при активных целях.
- R6. Импульсивные покупки (опционально, пост-MVP).

Каждая рекомендация: текст, обоснование, действие, severity (info/warning/critical), статус (новая/прочитана/применена/отклонена). Пересчёт: событийно + раз в сутки. Правила конфигурируемы (параметры в jsonb).

**FR-6. Цели накоплений**
- CRUD: название, сумма, дедлайн.
- Автоплан «сколько откладывать в месяц/неделю».
- Прогресс-бар, история пополнений, алёрт при отставании.

**FR-7. Еженедельный дайджест**
Планировщик (понедельник): сводка в приложении + сообщение в Telegram (расходы, топ-категории, прогресс целей, 1–3 рекомендации).

## 4. Нефункциональные требования

| Параметр | Требование |
|---|---|
| Производительность | API p95 < 300 мс (до 10k операций у пользователя) |
| Парсинг SMS | > 95% корректного распознавания поддерживаемых банков |
| Доступность | downtime при деплое < 1 мин |
| Безопасность | argon2/bcrypt, TLS, маскирование карт в логах, удаление аккаунта с данными |
| Локализация | RU (готовность к EN) |
| Валюты | ₽ MVP, amount + currency с первого дня |
| Тестирование | Unit ≥ 70% на парсер и движок правил |

## 5. Технологический стек

- **Backend:** Java 21, Spring Boot 3.3, Spring Security (JWT), Spring Data JPA, Validation, PostgreSQL 16, Flyway, Telegram Bots API (long polling), Spring Scheduler, Maven.
- **Frontend:** Angular 18, TypeScript strict, standalone + Signals, ng2-charts (Chart.js), UI-кит на выбор (Tailwind или Angular Material), PWA — желательно в MVP.
- **Инфраструктура:** Docker Compose, GitHub Actions CI → CD на VPS по SSH, Nginx + Let's Encrypt.

## 7. Этапы разработки

| Этап | Содержание | Критерий выхода |
|---|---|---|
| 0. Скелет | Репозиторий, CI, docker-compose | ✅ Зелёный пайплайн |
| 1. Auth + профиль | Регистрация, JWT, роли, код привязки | Можно войти |
| 2. Транзакции | CRUD, категории, фильтры | Операции учитываются |
| 3. Бот + парсер | Привязка, приём SMS, 3 банка | SMS → операция |
| 4. Статистика | Дашборд, графики | Данные визуализированы |
| 5. Рекомендации | Движок R1–R5, лента | Советы на реальных данных |
| 6. Цели + дайджест | Цели, планировщик | Полный цикл MVP |
| 7. Харднинг | Тесты, бэкапы, удаление аккаунта | Готово к публикации |

---

## 8. Критерии приёмки MVP

1. Пересланное SMS → операция в учёте ≤ 5 сек с категорией.
2. Дашборд: баланс, расходы/доходы месяца, диаграмма по категориям.
3. ≥ 3 вида персональных рекомендаций на реальных данных.
4. Цель с планом и прогрессом.
5. Еженедельный дайджест в Telegram.
6. Изоляция данных между пользователями.
7. Парсер ≥ 95% на тестовом наборе SMS.

---

## 9. Риски

| Риск | Митигация |
|---|---|
| Банки меняют формат SMS | Шаблоны в конфиге, алёрт на падение доли успеха |
| Не-SMS сообщения | Мягкий отказ + ручной разбор |
| Лимиты Telegram | Webhook, очередь |
| Мультивалютность рано | currency с первого дня |
| Поверхностные советы | Обоснование + обратная связь «применена/отклонена» |
